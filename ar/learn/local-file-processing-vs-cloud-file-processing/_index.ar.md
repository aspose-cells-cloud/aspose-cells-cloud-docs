معالجة الملفات محليًا ومعالجتها في السحابة هي نماذج مختلفة لإدارة البيانات، وتمتازان باختلافات جوهرية في البنية التحتية لتخزين الملفات، والمعالجة التجارية، والوصول، وهيكل التكلفة، والأمان، والسيناريوهات المناسبة. والاختلافات الرئيسية بين النموذجين هي كالتالي:

**الاحتياجات المسبقة:** قبل استخدام الأمثلة، تأكد من امتلاكك حسابًا صالحًا في Aspose.Cells Cloud، وتثبيت أحدث إصدار من حزمة التطوير (SDK)، واستعداد مُعرِّف العميل (Client Id) وسر مُعرِّف العميل (Client Secret) للمصادقة.

## ١. موقع تخزين الملفات والبنية التحتية

- الملفات المحلية:

  - تُخزَّن الملفات على أجهزة مادية يملكها المستخدم أو يديرها، مثل قرص التخزين في الحاسوب الشخصي أو الخوادم الداخلية أو أقراص التخزين الخارجية. **يمكنك توجيه عميل Cells Cloud مباشرة إلى ملف موجود على أي جهاز تخزين محلي.**
  - يمتلك العميل سيطرة مادية كاملة على оборудاته.
  - تقع مسؤولية شراء وصيانة وترقية واعتبار البنية التحتية (مثل إيقاف التشغيل أو الاستبدال) على عاتق المستخدم أو مؤسسته.

```python
from asposecellscloud.apis.cells_api import CellsApi
from asposecellscloud.requests import ConvertSpreadsheetRequest

# تهيئة CellsApi
api = CellsApi('YourCellsCloudClientId', 'YourCellsCloudClientSecret')

# تحويل ملف Excel محلي إلى PDF
api.convert_spreadsheet(
    ConvertSpreadsheetRequest('D:\\Data\\BookSales.xlsx', "pdf"),
    local_outpath="BookSales.pdf"
)
```

**مرجع واجهة برمجة التطبيقات – تحويل جدول العمل**

| الطريقة                |Verb HTTP| نقطة النهاية (Endpoint) | المُعطَلات (المفتاح)                                | الاستجابات                            |
|-----------------------|---------|------------------------|---------------------------------------------------|---------------------------------------|
| `convert_spreadsheet` | POST    | `/cells/convert`       | `inputFile` – مسار الملف المصدر<br>`format` – تنسيق الوجهة (مثل `pdf`) | `200 OK` – تم التحويل بنجاح<br>`400 Bad Request` – مُعطَلات غير صالحة<br>`401 Unauthorized` – فشل المصادقة |

- الملفات في السحابة:

  - تُخزَّن الملفات في مراكز بيانات بعيدة تديرها مزوِّدي خدمات السحابة من طرف ثالث (مثل خدمة التخزين في Aspose Cloud، Dropbox، AWS، Google Cloud، Microsoft Azure). **يمكن ربط AWS وDropbox وGoogle Cloud وMicrosoft Azure جميعها بخدمة تخزين Aspose Cloud.**
  - ي الوصول إلى هذه الملفات عبر الإنترنت، بغض النظر عن موقع وصيانة العتاد الأساسي.
  - تقع مسؤولية البنية التحتية على عاتق مزوِّد خدمة السحابة، ويستخدم المستخدمون الخدمة حسب الحاجة.

```python
from asposecellscloud.apis.cells_api import CellsApi
from asposecellscloud.requests import (
    UploadFileRequest,
    ExportSpreadsheetAsFormatRequest,
    SaveSpreadsheet_asRequest,
)

# تهيئة CellsApi
api = CellsApi('YourCellsCloudClientId', 'YourCellsCloudClientSecret')

# رفع ملف محلي إلى تخزين سحابي
api.upload_file(
    UploadFileRequest(
        "D:\\Data\\EmployeeSalesSummary.xlsx",
        "PythonSDK/EmployeeSalesSummary.xlsx"
    )
)

# تصدير ملف سحابي إلى تنسيق محدد على التخزين المحلي
api.export_spreadsheet_as_format(
    ExportSpreadsheetAsFormatRequest(
        "EmployeeSalesSummary.xlsx",
        "pdf",
        folder="PythonSDK"
    ),
    local_outpath="D:\\DataOutput\\EmployeeSalesSummary.pdf"
)

# تعريف المجلد البعيد (استبدل باسم المجلد الفعلي إذا اختلف)
RemoteFolder = "PythonSDK"

# حفظ ملف Excel في Cells Cloud كملف بتنسيق آخر داخل Cells Cloud
api.save_spreadsheet_as(
    SaveSpreadsheet_asRequest(
        "EmployeeSalesSummary.xlsx",
        "pdf",
        folder=RemoteFolder
    )
)
```

**مرجع واجهة برمجة التطبيقات – عمليات الملفات في السحابة**

| الطريقة                     |Verb HTTP| نقطة النهاية (Endpoint)          | المُعطَلات (المفتاح)                                                                                   | الاستجابات                                |
|----------------------------|---------|----------------------------------|-------------------------------------------------------------------------------------------------------|-------------------------------------------|
| `upload_file`              | PUT     | `/cells/storage/file`            | `localPath` – مسار الملف المحلي<br>`remotePath` – المسار الوجهة في التخزين السحابي                   | `200 OK` – تم الرفع بنجاح<br>`401 Unauthorized` |
| `export_spreadsheet_as_format` | POST  | `/cells/{name}/export`           | `name` – اسم الملف السحابي<br>`format` – تنسيق الوجهة (مثل `pdf`)<br>`folder` – مجلد اختياري         | `200 OK` – تم التصدير بنجاح<br>`400 Bad Request` |
| `save_spreadsheet_as`      | POST    | `/cells/{name}/saveas`           | `name` – اسم الملف السحابي<br>`format` – تنسيق الوجهة<br>`folder` – مجلد الوجهة                     | `200 OK` – تم الحفظ بنجاح<br>`401 Unauthorized` |

## ٢. المعالجة التجارية

مهما كانت طريقة المعالجة (محليًا أو في السحابة)، تتم جميع العمليات التجارية في خوادم Cells Cloud، **لذلك يتطلب ذلك دعم إنترنت**.

## ٣. الوصول إلى البيانات

- المعالجة المحلية:

  - يكون الوصول عادةً مقتصرًا على الجهاز نفسه.
  - يصعُب دعم التعاون بين عدة أشخاص.
  - صعوبة في تغيير الجهاز أو الموقع.

- المعالجة في السحابة:

  - إمكانية الوصول إلى الملفات من أي جهاز (حاسوب، هاتف، لوحي) وفي أي وقت ومكان، طالما توفر اتصال بالإنترنت.
  - دعم طبيعي للتعاون الفوري بين عدة أشخاص؛ حيث يمكن لعدة مستخدمين تعديل نفس المستند في الوقت نفسه، ويقوم النظام تلقائيًا بإدارة الإصدارات.
  - مرونة عالية في التنقّل، ودعم مرن للعمل، وإمكانية العمل عن بُعد.

## ٤. هيكل التكلفة والأمان

- الملفات المحلية:

  - يتطلب مرحلة أولية استثمارًا رأسماليًا مرتفعًا، مما يؤدي إلى تكاليف تشغيلية إضافية لاحقًا.
  - تُدار أمان الملفات المادي وأمان الشبكة بالكامل من قِبل المستخدمين أنفسهم.

- الملفات في السحابة:

  - استثمار أولي منخفض، وتكاليف تشغيلية أساسية، ونظام الدفع حسب الاستخدام.
  - تقع مسؤولية الأمان والسلامة على عاتق مزوِّد خدمة السحابة.

## ٥. السيناريوهات المناسبة

- الملفات المحلية: يمكن تنفيذ عمليات الملفات محليًا فقط.  
- الملفات في السحابة: يمكن تنفيذ عمليات الملفات محليًا أو في السحابة.  

**ملاحظات / قيود:** تدعم واجهة برمجة التطبيقات (API) ملفات تصل إلى ٢٠٠ ميغابايت فقط للمعالجة في السحابة، ولا يمكن تحويل سوى التنسيقات المذكورة في الوثائق. وقد تؤثر تأخيرات الشبكة على وقت المعالجة لجداول العمل الكبيرة.
