تقدم نقطة النهاية **DecomposeUserTask** واجهة REST لتحويل وصف مهمّة صيغته حُرّة إلى خطة إجرائية تفصيلية متسلسلة تلتزم بمعايير SMART. وتقوم هذه الخدمة تلقائيًا بتخصيص تقديرات زمنية مبنية على الساعات، وتنسيق المخرجات للاستيراد بما يتوافق مع Redmine، وإنشاء عُقد مُحطّات رئيسية للمشروع. وببساطة، عند تزويدها بقائمة المهمّة الخام وتقديرات زمنية اختيارية، تُعيد واجهة برمجة التطبيقات ملفًا جاهزًا للاستخدام (CSV أو XLSX أو غيرها) يمكن استيراده مباشرة في أدوات إدارة المشاريع، ما يُسهّل تحليل المهمّة ويقلّل الجهد اليدوي.

## **واجهة برمجة تطبيقات تحليل المهمة المستخدم**

### واجهة برمجة التطبيقات عبر الويب

```http
PUT https://api.aspose.cloud/v4.0/cells/ai/task/decompose
```

### **الأمان والمصادقة**

تتميز واجهات برمجة تطبيقات Aspose.Cells Cloud بالأمان وتتطلب <a href="https://docs.aspose.cloud/total/getting-started/rest-api-overview/authenticating-api-requests/" rel="noopener noreferrer">مصادقة مبنية على رمز JWT</a>.

### **مُعاملات الطلب:**

| اسم المُعامل       | النوع   | الموقع | إجباري/اختياري | الوصف                                                                                                                                                                                                                              |
| :---------------- | :------ | :----- | :---------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TaskDescription   | نصّ    | جسم الطلب | إجباري          | وصف نصّي بسيط لهدف المستخدم العام. تقوم الخدمة بتحليل هذا الوصف وتوليد مهام فردية. مثال: «إطلاق حملة تسويقية للربع الثالث، بما في ذلك إنشاء المحتوى، وإرسال رسائل إلكترونية جماعية، وإعلانات وسائل التواصل الاجتماعي.» |

### **الاستجابة**

استجابة ناجحة (200 OK)  
Content‑Type: `application/octet-stream` (تدفق ملف ثنائي)

الرؤوس:

- `Content-Disposition: attachment; filename="DecomposedTaskPlan.xlsx"`
- `Content-Length: <الحجم بالبايت>`

يُستخدم نفس الهيكل لتنسيقات XLSX/ODS، مع توزيع الأعمدة في ورقة العمل الأولى.

**رموز حالة HTTP**

| الرمز | المعنى                   | الوصف                                                                 |
| ----- | ------------------------- | --------------------------------------------------------------------- |
| 200   | OK (نجاح)                | تطبيق الفلتر بنجاح؛ تحتوي الاستجابة على تفاصيل العملية.             |
| 400   | Bad Request (طلب غير صالح) | مُعاملات مفقودة أو غير صالحة (مثل نوع ملف غير مدعوم).                |
| 401   | Unauthorized (غير مُصرّح له) | رمز JWT غير صالح أو مفقود.                                          |
| 413   | Payload Too Large (حمولة كبيرة جدًا) | تجاوز حجم الملف المرفوع الحد المسموح.                              |
| 500   | Internal Server Error (خطأ داخلي في الخادم) | خطأ غير متوقع في الخادم.                                           |

**مثال على استجابة خطأ (400 Bad Request)**

```json
{
  "code": "InvalidParameter",
  "message": "حقل 'TaskDescription' إجباري ولا يمكن أن يكون فارغًا."
}
```

**مثال على جسم الطلب (JSON)**

```json
{
  "TaskDescription": "تطوير واجهة برمجة تطبيقات ويب لميزة تقسيم المهام في النظام القائم."
}
```

**مثال على الاستجابة**  
تُعيد واجهة برمجة التطبيقات تدفقًا ثنائيًا يحتوي على الملف المُولّد. ولعرض أول بضعة صفوف من استجابة CSV، يمكنك فك تشفير التدفق وعرض صف الرأس، مثالًا:

```
ID,Subject,Trucker,Estimated Duration,Description
1	جمع المتطلبات لواجهة برمجة تطبيقات تقسيم المهام	محلل الأعمال	8	جمع المتطلبات الوظيفية وغير الوظيفية وقصص المستخدم ومعايير القبول لواجهة تقسيم المهام الجديدة.
2	مواصفات واجهة برمجة التطبيقات (OpenAPI)	محلل الأعمال	6	تحديد عقد OpenAPI لـ POST /tasks/split، بما في ذلك مخطط الطلب وأشكال الاستجابة وأكواد الأخطاء ومتطلبات الأمان.
```

## أين يجب استخدام واجهة برمجة تطبيقات تحليل المهمة المستخدم؟

- **بدء المشروع**: تحويل ملخّص المشروع عالي المستوى إلى قائمة مهام متوافقة مع Redmine تتضمن تقديرات زمنية، مما يمكّن من التخطيط الفوري للسباقات (Sprints).
- **أتمتة التسويق**: تقسيم أهداف الحملة إلى خطوات قابلة للتنفيذ، وتصديرها كملف CSV واستيراده في أدوات إدارة المهام لتنسيق العمل عبر الفِرَق.
- **تخصيص الموارد**: إنشاء تقديرات زمنية مبنية على الساعات لكل مهمة فرعية، ما يسمح للمديرين بتوزيع الأعباء بين أعضاء الفريق قبل بدء المشروع.
- **تتبع المُحطّات الرئيسية**: إنشاء عُقد المُحطّات الرئيسية تلقائيًا، مع إمكانية مزامنتها مع أدوات مخططات جانت، لضمان وضوح المخرجات لكل مرحلة.

## لماذا يجب استخدام واجهة برمجة تطبيقات تحليل المهمة المستخدم؟

- **مخرجات متوافقة مع معايير SMART**: تضمن كل مهمة مُولّدة الامتثال لمتطلبات التحديد، والقياس، والقابلية للتحقيق، والصلة، والربط الزمني.
- **تقدير زمني مدمج مبني على الساعات**: يلغي الحاجة إلى الحسابات اليدوية ويحسّن دقة التنبؤات.
- **تنسيقات ملفات جاهزة للاستيراد (CSV، XLSX، إلخ)**: تسهّل التكامل مع Redmine وJira وAzure DevOps ومنصات إدارة المشاريع الأخرى.
- **أتمتة بطلب واحد**: تمكّن من تحليل المهمة عبر طلب واحد فقط، ما يُسرّع بدء المشروع ويقلّل الجهد اليدوي.
