การประมวลผลไฟล์แบบโลคัลและการประมวลผลไฟล์บนคลาวด์เป็นรูปแบบการจัดการข้อมูลที่แตกต่างกัน โดยมีความแตกต่างอย่างมีนัยสำคัญในด้านโครงสร้างพื้นฐานการจัดเก็บไฟล์ การประมวลผลทางธุรกิจ การเข้าถึง โครงสร้างค่าใช้จ่าย ความปลอดภัย และสถานการณ์การใช้งานที่เหมาะสม ความแตกต่างหลักมีดังนี้:

**ข้อกำหนดเบื้องต้น:** ก่อนใช้งานตัวอย่าง คุณจำเป็นต้องมีบัญชี Aspose.Cells Cloud ที่ใช้งานได้ ติดตั้ง SDK เวอร์ชันล่าสุด และเตรียม Client ID และ Client Secret ของคุณสำหรับการยืนยันตัวตน

## 1. ตำแหน่งที่ตั้งและโครงสร้างพื้นฐานการจัดเก็บไฟล์

- ไฟล์แบบโลคัล:

  - ไฟล์ถูกจัดเก็บบนอุปกรณ์กายภาพที่ผู้ใช้เป็นเจ้าของหรือดูแล เช่น ฮาร์ดไดรฟ์ของคอมพิวเตอร์ส่วนบุคคล เซิร์ฟเวอร์ภายใน หรือฮาร์ดไดรฟ์ภายนอก **คุณสามารถชี้ไปยังไฟล์ที่อยู่บนอุปกรณ์จัดเก็บแบบโลคัลใดๆ ได้โดยตรงผ่านไคลเอนต์ Cells Cloud**
  - ลูกค้าควบคุมฮาร์ดแวร์ด้วยตนเองอย่างสมบูรณ์
  - การจัดซื้อ การดูแลรักษา การอัปเกรด และการเลิกใช้งานโครงสร้างพื้นฐานเป็นหน้าที่ของผู้ใช้หรือองค์กรของผู้ใช้

```python
from asposecellscloud.apis.cells_api import CellsApi
from asposecellscloud.requests import ConvertSpreadsheetRequest

# เริ่มต้น CellsApi
api = CellsApi('YourCellsCloudClientId', 'YourCellsCloudClientSecret')

# แปลงไฟล์ Excel แบบโลคัลเป็น PDF
api.convert_spreadsheet(
    ConvertSpreadsheetRequest('D:\\Data\\BookSales.xlsx', "pdf"),
    local_outpath="BookSales.pdf"
)
```

**อ้างอิง API – แปลงสเปรดชีต**

| เมธอด                 | HTTP Verb | Endpoint            | พารามิเตอร์ (ชื่อ)                                | การตอบกลับ            |
|-----------------------|-----------|---------------------|--------------------------------------------------|----------------------|
| `convert_spreadsheet` | POST      | `/cells/convert`    | `inputFile` – ที่อยู่ไฟล์ต้นทาง<br>`format` – รูปแบบปลายทาง (เช่น `pdf`) | `200 OK` – แปลงสำเร็จ<br>`400 Bad Request` – พารามิเตอร์ไม่ถูกต้อง<br>`401 Unauthorized` – การยืนยันตัวตนล้มเหลว |

- ไฟล์บนคลาวด์:

  - ไฟล์ถูกจัดเก็บในศูนย์ข้อมูลระยะไกลซึ่งผู้ให้บริการคลาวด์ภายนอกดำเนินการ (เช่น Aspose cloud storage, Dropbox, AWS, Google Cloud, Microsoft Azure) **AWS, Dropbox, Google Cloud และ Microsoft Azure สามารถเชื่อมต่อกับพื้นที่จัดเก็บบนคลาวด์ของ Aspose ได้ทั้งหมด**
  - ลูกค้าเข้าถึงไฟล์เหล่านี้ผ่านอินเทอร์เน็ต ไม่ว่าจะอยู่ที่ใดก็ตาม ไม่ต้องกังวลเกี่ยวกับการดูแลอุปกรณ์พื้นฐาน
  - โครงสร้างพื้นฐานเป็นหน้าที่ของผู้ให้บริการคลาวด์ ผู้ใช้สามารถเรียกใช้งานตามความต้องการ

```python
from asposecellscloud.apis.cells_api import CellsApi
from asposecellscloud.requests import (
    UploadFileRequest,
    ExportSpreadsheetAsFormatRequest,
    SaveSpreadsheetAsRequest,
)

# เริ่มต้น CellsApi
api = CellsApi('YourCellsCloudClientId', 'YourCellsCloudClientSecret')

# อัปโหลดไฟล์แบบโลคัลไปยังพื้นที่จัดเก็บบนคลาวด์
api.upload_file(
    UploadFileRequest(
        "D:\\Data\\EmployeeSalesSummary.xlsx",
        "PythonSDK/EmployeeSalesSummary.xlsx"
    )
)

# ส่งออกไฟล์บนคลาวด์เป็นไฟล์รูปแบบที่ระบุไปยังพื้นที่จัดเก็บแบบโลคัล
api.export_spreadsheet_as_format(
    ExportSpreadsheetAsFormatRequest(
        "EmployeeSalesSummary.xlsx",
        "pdf",
        folder="PythonSDK"
    ),
    local_outpath="D:\\DataOutput\\EmployeeSalesSummary.pdf"
)

# กำหนดโฟลเดอร์ระยะไกล (เปลี่ยนชื่อโฟลเดอร์ตามที่คุณใช้งานจริง)
RemoteFolder = "PythonSDK"

# บันทึกไฟล์ Excel บน Cells Cloud ให้อยู่ในรูปแบบอื่นบน Cells Cloud
api.save_spreadsheet_as(
    SaveSpreadsheetAsRequest(
        "EmployeeSalesSummary.xlsx",
        "pdf",
        folder=RemoteFolder
    )
)
```

**อ้างอิง API – การดำเนินการกับไฟล์บนคลาวด์**

| เมธอด                     | HTTP Verb | Endpoint                     | พารามิเตอร์ (ชื่อ)                                                                                 | การตอบกลับ                                    |
|----------------------------|-----------|------------------------------|---------------------------------------------------------------------------------------------------|----------------------------------------------|
| `upload_file`              | PUT       | `/cells/storage/file`        | `localPath` – ที่อยู่ไฟล์แบบโลคัล<br>`remotePath` – ตำแหน่งปลายทางในพื้นที่จัดเก็บบนคลาวด์                     | `200 OK` – อัปโหลดสำเร็จ<br>`401 Unauthorized` |
| `export_spreadsheet_as_format` | POST      | `/cells/{name}/export`       | `name` – ชื่อไฟล์บนคลาวด์<br>`format` – รูปแบบปลายทาง (เช่น `pdf`)<br>`folder` – โฟลเดอร์ (ระบุหรือไม่ก็ได้) | `200 OK` – ส่งออกสำเร็จ<br>`400 Bad Request` |
| `save_spreadsheet_as`      | POST      | `/cells/{name}/saveas`       | `name` – ชื่อไฟล์บนคลาวด์<br>`format` – รูปแบบปลายทาง<br>`folder` – โฟลเดอร์ปลายทาง            | `200 OK` – บันทึกสำเร็จ<br>`401 Unauthorized` |

## 2. การประมวลผลทางธุรกิจ

ไม่ว่าจะเป็นการประมวลผลไฟล์แบบโลคัลหรือบนคลาวด์ การประมวลผลทางธุรกิจทั้งหมดจะดำเนินการบนเซิร์ฟเวอร์ของ Cells Cloud **ดังนั้นจึงจำเป็นต้องมีการเชื่อมต่ออินเทอร์เน็ต**

## 3. การเข้าถึงข้อมูล

- การประมวลผลไฟล์แบบโลคัล:

  - การเข้าถึงมักจำกัดเฉพาะอุปกรณ์นั้นๆ เท่านั้น
  - การทำงานร่วมกันหลายผู้ใช้ทำได้ยาก
  - ไม่สะดวกเมื่อเปลี่ยนอุปกรณ์หรือสถานที่

- การประมวลผลไฟล์บนคลาวด์:

  - เข้าถึงไฟล์ได้จากทุกอุปกรณ์ (คอมพิวเตอร์ โทรศัพท์ มือถือ) ทุกที่ทุกเวลา ตราบใดที่มีการเชื่อมต่ออินเทอร์เน็ต
  - รองรับการทำงานร่วมกันแบบเรียลไทม์หลายผู้ใช้อย่างเป็นธรรมชาติ ผู้ใช้หลายคนสามารถแก้ไขเอกสารเดียวกันพร้อมกัน ระบบจัดการเวอร์ชันให้อัตโนมัติ
  - มีความคล่องตัวสูง รองรับการทำงานแบบยืดหยุ่น และการทำงานจากระยะไกล

## 4. โครงสร้างค่าใช้จ่ายและความปลอดภัย

- ไฟล์แบบโลคัล:

  - ต้องใช้เงินทุนสูงในระยะเริ่มต้น ซึ่งนำไปสู่ค่าใช้จ่ายเพิ่มเติมสำหรับการสนับสนุนการดำเนินงานในภายหลัง
  - ผู้ใช้ควบคุมความปลอดภัยทางกายภาพและความปลอดภัยของเครือข่ายด้วยตนเอง

- ไฟล์บนคลาวด์:

  - ลงทุนเริ่มต้นต่ำ ส่วนใหญ่เป็นค่าใช้จ่ายในการดำเนินงาน จ่ายตามการใช้งานจริง
  - ผู้ให้บริการคลาวด์รับผิดชอบด้านความปลอดภัยและความสมบูรณ์ของข้อมูล

## 5. สถานการณ์การใช้งานที่เหมาะสม

- ไฟล์แบบโลคัล: การดำเนินการกับไฟล์ทำได้เฉพาะภายในเครื่องเท่านั้น  
- ไฟล์บนคลาวด์: การดำเนินการกับไฟล์ทำได้ทั้งภายในเครื่องและบนคลาวด์  

**หมายเหตุ / ข้อจำกัด:** API รองรับไฟล์ขนาดสูงสุด 200 เมกะไบต์สำหรับการประมวลผลบนคลาวด์ และสามารถแปลงได้เฉพาะรูปแบบที่ระบุไว้ในเอกสารคู่มือเท่านั้น ความล่าช้าของเครือข่ายอาจส่งผลต่อเวลาการประมวลผลสำหรับสเปรดชีตขนาดใหญ่
