endpoint **DecomposeUserTask** มี REST endpoint เพื่อแปลงคำอธิบายงานแบบเสรีให้เป็นแผนการดำเนินการแบบละเอียดและตามลำดับที่สอดคล้องกับเกณฑ์ SMART โดยอัตโนมัติจัดสรรการประมาณเวลาเป็นชั่วโมง จัดรูปแบบผลลัพธ์สำหรับการนำเข้าแบบเข้ากันได้กับ Redmine และสร้างโหนดระดับมิลสโตนของโครงการ โดยให้เฉพาะรายการงานดิบและการประมาณเวลา (ถ้ามี) API จะส่งกลับไฟล์พร้อมใช้งาน (CSV, XLSX เป็นต้น) ที่สามารถนำเข้าโดยตรงลงในเครื่องมือจัดการโครงการ ช่วยอัตโนมัติการย่อยงานและลดภาระงานด้วยตนเอง

## **API ย่อยงานผู้ใช้**

### Web API

```http
PUT https://api.aspose.cloud/v4.0/cells/ai/task/decompose
```

### **ความปลอดภัยและการยืนยันตัวตน**

Aspose.Cells Cloud APIs มีความปลอดภัยและต้องใช้ <a href="https://docs.aspose.cloud/total/getting-started/rest-api-overview/authenticating-api-requests/" rel="noopener noreferrer">การยืนยันตัวตนด้วย JWT token</a>

### **พารามิเตอร์คำขอ:**

| ชื่อพารามิเตอร์ | ประเภท | ตำแหน่ง | จำเป็น/ไม่จำเป็น | คำอธิบาย                                                                                                                                                                                                                              |
| :-------------- | :----- | :------- | :---------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TaskDescription | string | Body     | จำเป็น            | คำอธิบายวัตถุประสงค์โดยรวมของผู้ใช้ในรูปแบบข้อความธรรมดา บริการจะแยกวิเคราะห์คำอธิบายนี้และสร้างงานย่อยต่างๆ ตัวอย่าง: “เปิดตัวแคมเปญการตลาดสำหรับไตรมาสที่ 3 ประกอบด้วยการสร้างเนื้อหา การส่งอีเมลแบบบูรณาการ และโฆษณาบนโซเชียลมีเดีย” |

### **การตอบกลับ**

การตอบกลับที่สำเร็จ (200 OK)  
Content‑Type: `application/octet-stream` (สตรีมไฟล์ไบนารี)

หัวเรื่อง:

- `Content-Disposition: attachment; filename="DecomposedTaskPlan.xlsx"`
- `Content-Length: <ขนาดเป็นไบต์>`

โครงสร้างเดียวกันนี้ใช้สำหรับรูปแบบ XLSX/ODS โดยคอลัมน์จะอยู่ในแผ่นงานแรก

**รหัสสถานะ HTTP**

| รหัส | ความหมาย              | คำอธิบาย                                                          |
| ---- | --------------------- | ----------------------------------------------------------------- |
| 200  | สำเร็จ (OK)           | ใช้ตัวกรองเรียบร้อยแล้ว; การตอบกลับมีรายละเอียดของ оперATION |
| 400  | คำขอไม่ถูกต้อง (Bad Request) | พารามิเตอร์ขาดหายหรือไม่ถูกต้อง (เช่น ประเภทไฟล์ที่ไม่รองรับ)   |
| 401  | ไม่ได้รับอนุญาต (Unauthorized) | JWT token ไม่ถูกต้องหรือขาดหาย                                   |
| 413  | ข้อมูลหนักเกินไป (Payload Too Large) | ไฟล์ที่อัปโหลดเกินขีดจำกัดขนาด                               |
| 500  | ข้อผิดพลาดภายในเซิร์ฟเวอร์ (Internal Server Error) | เกิดข้อผิดพลาดที่ไม่คาดคิดบนเซิร์ฟเวอร์                        |

## ควรใช้ API ย่อยงานผู้ใช้ในกรณีใด?

- **เริ่มต้นโครงการ**: แปลงสรุปโครงการระดับสูงเป็นรายการงานที่เข้ากันได้กับ Redmine พร้อมการประมาณเวลา ทำให้สามารถวางแผน sprint ได้ทันที
- **อัตโนมัติการตลาด**: ย่อยวัตถุประสงค์แคมเปญออกเป็นขั้นตอนที่ดำเนินการได้ นำออกเป็น CSV และนำเข้าสู่เครื่องมือจัดการงานเพื่อประสานงานระหว่างทีม
- **การจัดสรรทรัพยากร**: สร้างการประมาณเวลาเป็นชั่วโมงสำหรับงานย่อยแต่ละรายการ ช่วยให้ผู้จัดการสามารถสมดุลภาระงานระหว่างสมาชิกในทีมก่อนเริ่มโครงการ
- **การติดตามมิลสโตน**: สร้างโหนดมิลสโตนโดยอัตโนมัติที่สามารถซิงค์กับเครื่องมือแผนภาพแกนต์ (Gantt-chart) เพื่อให้แต่ละเฟสมีผลลัพธ์ที่ชัดเจน

## เหตุใดจึงควรใช้ API ย่อยงานผู้ใช้?

- **ผลลัพธ์สอดคล้องเกณฑ์ SMART** รับประกันว่างานแต่ละงานที่สร้างขึ้นตรงตามเกณฑ์เฉพาะเจาะจง, วัดผลได้, ทำได้จริง, เกี่ยวข้อง และมีเวลาจำกัด
- **การประมาณเวลาเป็นชั่วโมงแบบฝังตัว** ช่วยลดความจำเป็นในการคำนวณด้วยตนเองและเพิ่มความแม่นยำในการพยากรณ์
- **รูปแบบไฟล์พร้อมนำเข้า** (CSV, XLSX เป็นต้น) รองรับการผนวกเข้ากับ Redmine, Jira, Azure DevOps และแพลตฟอร์มจัดการโครงการอื่นๆ
- **การอัตโนมัติด้วยคำขอเพียงครั้งเดียว** ทำให้สามารถย่อยงานผ่านคำขอเพียงครั้งเดียว เร่งการเริ่มต้นโครงการและลดภาระงานด้วยตนเอง
