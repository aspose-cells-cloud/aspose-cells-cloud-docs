ผสานไฟล์ Excel ที่เก็บไว้ในคลาวด์เข้ากับสเปรดชีตอื่นๆ ได้อย่างรวดเร็วด้วย Aspose.Cells Cloud API และระบุรูปแบบข้อมูลผลลัพธ์และตำแหน่งที่จัดเก็บได้

## API ผสานสเปรดชีตแบบรีโมต

ก่อนเรียกใช้การดำเนินการนี้ โปรดตรวจสอบให้แน่ใจว่าคุณมี:

- **โทเค็น JWT** ที่ถูกต้อง (ดูคู่มือการยืนยันตัวตน)
- สมุดงานต้นทางและไฟล์ทั้งหมดที่ต้องการผสานอัปโหลดไว้ในพื้นที่จัดเก็บคลาวด์ของคุณแล้ว
- สิทธิ์ที่เหมาะสมในการอ่านจากโฟลเดอร์ต้นทางและเขียนไปยังโฟลเดอร์เป้าหมาย

### Web API

```http
PUT https://api.aspose.cloud/v4.0/cells/{name}/merge/spreadsheet
```

### **ความปลอดภัยและการยืนยันตัวตน**

Aspose.Cells Cloud APIs มีความปลอดภัยและต้องใช้ <a href="https://docs.aspose.cloud/total/getting-started/rest-api-overview/authenticating-api-requests/" rel="noopener noreferrer">การยืนยันตัวตนแบบใช้โทเค็น JWT</a>

### พารามิเตอร์คำขอ:

| ชื่อพารามิเตอร์ | ชนิดข้อมูล | Path/Query String/HTTPBody | คำอธิบาย                                                                                                                                                 |
| :--------------- | :-------- | :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| name             | String    | Path                       | ชื่อไฟล์สมุดงานต้นทางที่ต้องการผสาน                                                                                                                     |
| mergedSpreadsheet| String    | Query                      | รายชื่อไฟล์สเปรดชีตที่ต้องการผสานเข้ากับสมุดงานต้นทาง (คั่นด้วยเครื่องหมายจุลภาค)                                                                     |
| folder           | String    | Query                      | ตำแหน่งโฟลเดอร์ในพื้นที่จัดเก็บคลาวด์ที่มีสมุดงานต้นทาง                                                                                                 |
| outFormat        | String    | Query                      | รูปแบบที่ต้องการสำหรับไฟล์ผลลัพธ์ที่ผสานแล้ว (เช่น `XLSX`, `PDF`, `CSV`)                                                                                 |
| mergeInOneSheet  | Boolean   | Query                      | ตั้งค่าเป็น `true` เพื่อผสานข้อมูลทั้งหมดจากแหล่งต้นทางลงในแผ่นงานเดียว; ตั้งค่าเป็น `false` เพื่อสร้างแผ่นงานแยกสำหรับแต่ละไฟล์                         |
| storageName      | String    | Query                      | _(ไม่บังคับ)_ ชื่อพื้นที่จัดเก็บคลาวด์ที่สมุดงานต้นทางอยู่ หากไม่ระบุ จะใช้พื้นที่จัดเก็บค่าเริ่มต้น                                                      |
| outPath          | String    | Query                      | _(ไม่บังคับ)_ ตำแหน่งโฟลเดอร์เป้าหมายในพื้นที่จัดเก็บคลาวด์สำหรับบันทึกไฟล์ที่ผสานแล้ว หากไม่ระบุ ไฟล์จะถูกบันทึกไว้ในโฟลเดอร์ต้นทาง                     |
| outStorageName   | String    | Query                      | ชื่อพื้นที่จัดเก็บคลาวด์สำหรับบันทึกไฟล์ผลลัพธ์                                                                                                         |
| fontsLocation    | String    | Query                      | _(ไม่บังคับ)_ ตำแหน่งโฟลเดอร์ที่กำหนดเองสำหรับไฟล์ฟอนต์ที่ใช้ในการแปลงเป็นรูปภาพ/รูปแบบ PDF                                                             |
| region           | String    | Query                      | _(ไม่บังคับ)_ โลเคิล/ภูมิภาคสำหรับการจัดรูปแบบวันที่ ตัวเลข และสกุลเงินในไฟล์ผลลัพธ์ (เช่น `en-US`, `de-DE`)                                               |
| password         | String    | Query                      | _(ไม่บังคับ)_ รหัสผ่านที่จำเป็นสำหรับการเปิดสมุดงานต้นทางหากสมุดงานนั้นมีการป้องกันไว้                                                                   |

### คำตอบ

**สถานะ:** `200 OK`

```json
[
  {
    "Name": "ResponseFile",
    "DataType": {
      "Identifier": "File",
      "Reference": "Stream"
    }
  }
]
```

ไฟล์สามารถดาวน์โหลดได้โดยตรงหรือบันทึกไว้ที่ตำแหน่งที่ระบุโดย `outPath`

**รายละเอียดคำตอบที่สำเร็จ**

| โค้ดสถานะ | Content-Type               | คำอธิบาย                           |
| --------- | -------------------------- | ---------------------------------- |
| 200 OK    | `application/octet-stream` | สตรีมไบต์ของไฟล์สมุดงานที่ผสานแล้ว |

**โค้ดสถานะ HTTP**

| โค้ด | ความหมาย               | คำอธิบาย                                                               |
| ---- | --------------------- | --------------------------------------------------------------------- |
| 200  | OK                    | ใช้ตัวกรองสำเร็จ; คำตอบมีรายละเอียดการดำเนินการ                     |
| 400  | Bad Request           | พารามิเตอร์ขาดหายหรือไม่ถูกต้อง (เช่น ประเภทไฟล์ที่ไม่รองรับ)        |
| 401  | Unauthorized          | โทเค็น JWT ไม่ถูกต้องหรือขาดหาย                                       |
| 413  | Payload Too Large     | ไฟล์ที่อัปโหลดมีขนาดเกินขีดจำกัด                                     |
| 500  | Internal Server Error | เกิดข้อผิดพลาดของเซิร์ฟเวอร์ที่ไม่คาดคิด                             |

## ควรใช้ API ผสานสเปรดชีตแบบรีโมตในกรณีใด?

### การผสานข้อมูลระดับองค์กร

- **การรวมรายงานจากหลายแผนก** – รวมรายงาน Excel ที่ส่งมาจากแผนกการขาย การตลาด การเงิน และอื่นๆ
- **สรุปข้อมูลสาขา** – รวมข้อมูลผลการดำเนินงานจากสาขาทั่วโลก
- **การรวมข้อมูลจากพันธมิตร** – ผสานข้อมูลที่ส่งจากพันธมิตรหลายคนเข้าไว้ในสมุดงานเดียว

### กระบวนการทำงานประมวลผลเอกสารบนคลาวด์

- **การประมวลผลไฟล์ในพื้นที่จัดเก็บคลาวด์** – ผสานไฟล์ Excel ที่เก็บไว้ใน AWS S3, Azure Blob หรือ Google Cloud Storage ได้โดยตรง
- **การรวมข้อมูลจากหลายแหล่ง** – รวมไฟล์จากตำแหน่งคลาวด์ต่างๆ เข้าไว้ในสมุดงานเดียว
- **ท่อประมวลผลข้อมูลอัตโนมัติ** – ผสาน API เข้ากับกระบวนการ ETL เพื่อทำให้การผสานไฟล์เป็นไปโดยอัตโนมัติ

### การทำให้ระบบจัดการเอกสารเป็นอัตโนมัติ

- **การรวมเวอร์ชันต่างๆ** – ผสานเวอร์ชันต่างๆ ของแผนโครงการหรือสมุดงานงบประมาณ
- **เติมข้อมูลลงในเทมเพลต** – แทรกไฟล์ข้อมูลลงในเทมเพลตรายงานที่เป็นมาตรฐาน
- **การสร้างรายงานเป็นประจำ** – ทำให้รายงานสรุปรายสัปดาห์ รายเดือน และรายไตรมาสเป็นอัตโนมัติ

### การทำงานร่วมกันข้ามแพลตฟอร์ม

- **การทำงานร่วมกันกับทีมงานแบบรีโมต** – รวมงานที่ส่งมาจากสมาชิกในทีมที่กระจายตัวอยู่
- **การจัดระเบียบข้อมูลลูกค้า** – ผสานข้อมูลคำสั่งซื้อหรือข้อเสนอแนะจากลูกค้าหลายคน
- **สรุปข้อมูลซัพพลายเออร์** – รวมใบเสนอราคาหรือข้อมูลสินค้าจากซัพพลายเออร์หลายราย

## ทำไมควรใช้ API ผสานสเปรดชีตแบบรีโมต?

- **เป็นมิตรกับนักพัฒนา** – Aspose.Cells Cloud มี SDK สำหรับภาษาต่างๆ มากมาย ช่วยลดระยะเวลาการพัฒนาและมีเอกสารประกอบที่ครบถ้วน เมื่อเทียบกับการสร้างโซลูชันแบบกำหนดเอง วิธีนี้ช่วยลดภาระงานได้อย่างมาก
- **ลดค่าใช้จ่ายแรงงาน** – ลดความจำเป็นในการจัดบุคลากรเฉพาะเพื่อทำหน้าที่รวมเอกสารด้วยตนเอง
- **จ่ายตามการใช้งานจริง** – ไม่ต้องลงทุนล่วงหน้า; จ่ายเฉพาะค่าใช้จ่ายสำหรับการเรียกใช้ API ที่คุณใช้งานจริง
- **ไม่มีค่าใช้จ่ายในการดูแลรักษา** – ไม่มีเซิร์ฟเวอร์ให้ดูแล ไม่มีอัปเดตซอฟต์แวร์ และไม่มีปัญหาเรื่องความเข้ากันได้
