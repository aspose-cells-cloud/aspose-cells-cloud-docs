Локальная и облачная обработка файлов представляют собой разные парадигмы управления данными, существенно различающиеся по инфраструктуре хранения файлов, бизнес-процессам, доступу, структуре затрат, безопасности и применимым сценариям. Основные различия между ними следующие:

**Необходимые условия:** Перед использованием приведённых примеров убедитесь, что у вас есть действующая учётная запись Aspose.Cells Cloud, установлена последняя версия SDK, а также подготовлены ваши Client Id и Client Secret для аутентификации.

## 1. Расположение файлов и инфраструктура хранения

- Локальный файл:

  - Файлы хранятся на физических устройствах, которыми владеет или которыми управляет пользователь, например, жёстком диске персонального компьютера, внутренних серверах или внешних жёстких дисках. **Вы можете напрямую указать клиенту Aspose.Cells Cloud путь к файлу, расположенному на любом локальном хранилище.**
  - Покупатель полностью контролирует оборудование в физическом плане.
  - Покупка, обслуживание, обновление и вывод из эксплуатации инфраструктуры лежит на пользователе или его организации.

```python
from asposecellscloud.apis.cells_api import CellsApi
from asposecellscloud.requests import ConvertSpreadsheetRequest

# Инициализация CellsApi
api = CellsApi('YourCellsCloudClientId', 'YourCellsCloudClientSecret')

# Конвертация локального файла Excel в PDF
api.convert_spreadsheet(
    ConvertSpreadsheetRequest('D:\\Data\\BookSales.xlsx', "pdf"),
    local_outpath="BookSales.pdf"
)
```

**Справочник по API – Конвертация электронной таблицы**

| Метод                 | HTTP-метод | Эндпоинт            | Параметры (ключ)                                  | Ответы                         |
|-----------------------|------------|---------------------|--------------------------------------------------|--------------------------------|
| `convert_spreadsheet` | POST       | `/cells/convert`    | `inputFile` – путь к исходному файлу<br>`format` – целевой формат (например, `pdf`) | `200 OK` – конвертация успешна<br>`400 Bad Request` – неверные параметры<br>`401 Unauthorized` – ошибка аутентификации |

- Облачный файл:

  - Файлы хранятся в удалённых центрах обработки данных, которыми управляют сторонние поставщики облачных сервисов (облачное хранилище Aspose, Dropbox, AWS, Google Cloud, Microsoft Azure). **AWS, Dropbox, Google Cloud и Microsoft Azure могут быть подключены к облачному хранилищу Aspose.**
  - Покупатели получают доступ к этим файлам через Интернет, независимо от местоположения и обслуживания базового оборудования.
  - Ответственность за инфраструктуру несёт поставщик облачных сервисов, а пользователи используют её по требованию.

```python
from asposecellscloud.apis.cells_api import CellsApi
from asposecellscloud.requests import (
    UploadFileRequest,
    ExportSpreadsheetAsFormatRequest,
    SaveSpreadsheetAsRequest,
)

# Инициализация CellsApi
api = CellsApi('YourCellsCloudClientId', 'YourCellsCloudClientSecret')

# Загрузка локального файла в облачное хранилище
api.upload_file(
    UploadFileRequest(
        "D:\\Data\\EmployeeSalesSummary.xlsx",
        "PythonSDK/EmployeeSalesSummary.xlsx"
    )
)

# Экспорт облачного файла в указанный формат и сохранение на локальное хранилище
api.export_spreadsheet_as_format(
    ExportSpreadsheetAsFormatRequest(
        "EmployeeSalesSummary.xlsx",
        "pdf",
        folder="PythonSDK"
    ),
    local_outpath="D:\\DataOutput\\EmployeeSalesSummary.pdf"
)

# Определение удалённой папки (замените на ваше фактическое имя папки, если оно отличается)
RemoteFolder = "PythonSDK"

# Сохранение файла Excel из Aspose.Cells Cloud как файла другого формата в Aspose.Cells Cloud
api.save_spreadsheet_as(
    SaveSpreadsheetAsRequest(
        "EmployeeSalesSummary.xlsx",
        "pdf",
        folder=RemoteFolder
    )
)
```

**Справочник по API – Операции с облачными файлами**

| Метод                          | HTTP-метод | Эндпоинт                     | Параметры (ключ)                                                                                     | Ответы                                        |
|--------------------------------|------------|------------------------------|------------------------------------------------------------------------------------------------------|-----------------------------------------------|
| `upload_file`                  | PUT        | `/cells/storage/file`        | `localPath` – локальный путь к файлу<br>`remotePath` – целевой путь в облачном хранилище             | `200 OK` – загрузка успешна<br>`401 Unauthorized` |
| `export_spreadsheet_as_format` | POST       | `/cells/{name}/export`       | `name` – имя облачного файла<br>`format` – целевой формат (например, `pdf`)<br>`folder` – необязательная папка | `200 OK` – экспорт успешен<br>`400 Bad Request` |
| `save_spreadsheet_as`          | POST       | `/cells/{name}/saveas`       | `name` – имя облачного файла<br>`format` – целевой формат<br>`folder` – целевая папка               | `200 OK` – сохранение успешно<br>`401 Unauthorized` |

## 2. Бизнес-процессинг

Независимо от того, используется ли локальная или облачная обработка файлов, весь бизнес-процессинг выполняется на сервере Aspose.Cells Cloud, **поэтому требуется поддержка Интернета**.

## 3. Доступ к данным

- Локальная обработка файлов:

  - Доступ обычно ограничен самим устройством.
  - Сложно организовать совместную работу нескольких пользователей.
  - Неудобство при смене оборудования или местоположения.

- Облачная обработка файлов:

  - Доступ к файлам с любого устройства (компьютера, телефона, планшета) в любое время и в любом месте, если имеется подключение к Интернету.
  - Встроенная поддержка совместной работы нескольких пользователей в реальном времени: несколько пользователей могут редактировать один и тот же документ одновременно, а система автоматически управляет версиями.
  - Высокая мобильность, гибкая поддержка офисной работы и удалённая работа.

## 4. Структура затрат и безопасность

- Локальный файл:

  - На раннем этапе требуются значительные капитальные вложения. Это приводит к дополнительным расходам на эксплуатационную поддержку в дальнейшем.
  - Физическая и сетевая безопасность контролируются самими пользователями.

- Облачный файл:

  - Низкие первоначальные инвестиции, в основном операционные расходы, оплата по факту использования.
  - Безопасность и целостность данных являются ответственностью поставщика облачных сервисов.

## 5. Применимые сценарии

- Локальный файл: операции с файлами можно выполнять только локально.  
- Облачный файл: операции с файлами можно выполнять как локально, так и в облаке.  

**Примечания / Ограничения:** API поддерживает файлы размером до 200 МБ для облачной обработки, и конвертировать можно только форматы, перечисленные в документации. Задержка сети может повлиять на время обработки крупных электронных таблиц.
