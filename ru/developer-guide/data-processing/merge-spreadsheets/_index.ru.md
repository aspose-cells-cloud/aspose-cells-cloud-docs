Объедините несколько локальных файлов Excel, CSV или ODS в одну рабочую книгу и преобразуйте её в 30+ выходных форматов с помощью API Aspose.Cells Cloud.

### Web API

```http
PUT https://api.aspose.cloud/v4.0/cells/merge/spreadsheet
```

### **Безопасность и аутентификация**

API Aspose.Cells Cloud защищены и требуют <a href="https://docs.aspose.cloud/total/getting-started/rest-api-overview/authenticating-api-requests/" rel="noopener noreferrer">аутентификации на основе токена JWT</a>.

### **Параметры запроса**

| Имя параметра   | Тип     | Местоположение   | Описание                                                                                           |
| ----------------| ------- | ---------------- | -------------------------------------------------------------------------------------------------- |
| Spreadsheet     | Файл    | FormData         | Локальный файл электронной таблицы для загрузки. Поддерживаются форматы XLSX, XLS, CSV, ODS и др.  |
| outFormat       | Строка  | Query            | Желаемый выходной формат (например, `XLSX`, `PDF`, `CSV`, `HTML`). Поддерживается более 30 форматов. |
| mergeInOneSheet | Логическое | Query         | `true` → все данные объединяются в один рабочий лист; `false` → сохраняются исходные листы.        |
| outPath         | Строка  | Query (опционально) | Путь к папке в облаке, куда будет сохранён объединённый файл. Если не указан, используется путь по умолчанию. |
| outStorageName  | Строка  | Query            | Имя используемого облачного хранилища (по умолчанию или пользовательское).                        |
| fontsLocation   | Строка  | Query (опционально) | Папка в облаке, содержащая пользовательские шрифты для корректного отображения PDF/изображений.    |
| region          | Строка  | Query (опционально) | Локаль для форматирования чисел, дат и валют (например, `ru-RU`, `en-US`, `zh-CN`).               |
| password        | Строка  | Query (опционально) | Пароль для открытия защищённой электронной таблицы.                                               |

### **Ответ**

```json
{
  "Name": "ResponseFile",
  "DataType": {
    "Identifier": "File",
    "Reference": "Stream"
  }
}
```

Файл можно загрузить непосредственно или сохранить в путь, указанный в параметре `outPath`.

**Детали успешного ответа**

| Код состояния | Content‑Type              | Описание                                      |
| ------------- | ------------------------- | --------------------------------------------- |
| 200 OK        | `application/octet-stream`| Бинарный поток объединённой рабочей книги.    |

**Коды HTTP-статусов**

| Код | Значение                | Описание                                                       |
| ----| ----------------------- | -------------------------------------------------------------- |
| 200 | OK                      | Запрос успешно обработан; ответ содержит детали операции.     |
| 400 | Bad Request             | Отсутствуют или некорректны параметры (например, неподдерживаемый тип файла). |
| 401 | Unauthorized            | Неверный или отсутствующий JWT-токен.                          |
| 413 | Payload Too Large       | Загруженный файл превышает допустимый размер.                  |
| 500 | Internal Server Error   | Непредвиденная ошибка сервера.                                 |

## Где следует использовать API объединения электронных таблиц?

### **Образование и академические приложения**

- **Оценка студенческих работ** — объединение файлов с заданиями нескольких студентов для единых комментариев и оценивания.
- **Сбор исследовательских данных** — консолидация таблиц данных от разных экспериментальных групп.
- **Создание учебных материалов** — объединение упражнений из нескольких глав в одну рабочую тетрадь с вопросами.

### **Обработка и анализ данных**

- **Интеграция небольших наборов данных** — объединение файлов CSV или Excel, экспортированных из различных источников.
- **Предварительная обработка данных** — объединение соответствующих файлов перед анализом.
- **Заполнение шаблонов данными** — заполнение предустановленных отчётных шаблонов объединёнными данными.

### **Разработка и техническая поддержка**

- **Подготовка тестовых данных** — объединение нескольких файлов с тест-кейсами для автоматизированного тестирования.
- **Анализ журналов** — консолидация отчётов о системных журналах за разные периоды.
- **Управление конфигурацией** — объединение нескольких конфигурационных таблиц в единый конфигурационный файл.

## Почему следует использовать API объединения электронных таблиц?

- **Удобный для разработчика** — SDK доступны для множества языков программирования, что снижает усилия по разработке по сравнению с созданием собственного решения.
- **Снижение трудозатрат** — исключает необходимость в отдельном персонале для ручной консолидации документов.
- **Оплата по факту использования** — платите только за выполненные вызовы API; без предварительных инвестиций.
- **Отсутствие затрат на обслуживание** — не нужно обслуживать серверы, обновлять ПО или заботиться о совместимости.

## Как использовать API объединения электронных таблиц с помощью SDK

### **Спецификация OpenAPI**

<a href="https://reference.aspose.cloud/cells/#/DataProcessingController/MergeSpreadsheets" rel="noopener noreferrer">Спецификация OpenAPI</a> предоставляет машинно-читаемое описание API, позволяя напрямую взаимодействовать по протоколу REST.
