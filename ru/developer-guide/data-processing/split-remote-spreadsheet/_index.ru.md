Разделите большую рабочую книгу Excel, хранящуюся в облаке, на отдельные файлы по листам и экспортируйте каждый из них в 30+ выходных форматах, включая PDF, CSV, JSON, ODS и XPS, с помощью Aspose.Cells Cloud.

## **API для разделения удалённой электронной таблицы**

### Web API

```http
PUT https://api.aspose.cloud/v4.0/cells/{name}/split/spreadsheet
```

### **Безопасность и аутентификация**

Aspose.Cells Cloud API защищены и требуют <a href="https://docs.aspose.cloud/total/getting-started/rest-api-overview/authenticating-api-requests/" rel="noopener noreferrer">аутентификации на основе JWT-токена</a>.

### **Параметры запроса:**

| Имя параметра | Тип    | Путь / Строка запроса / Тело HTTP-запроса | Описание                                                                                                                           |
| :------------ | :----- | :---------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------- |
| name          | String | Путь                                      | Имя файла рабочей книги (например, `data.xlsx`), подлежащего разделению, расположенного в указанной папке облачного хранилища.    |
| folder        | String | Параметр запроса                          | Путь к папке облачного хранилища, где хранится исходная рабочая книга.                                                            |
| from          | Integer| Параметр запроса                          | Индекс начального листа (с нуля) для операции разделения. Например, `0` означает первый лист.                                      |
| to            | Integer| Параметр запроса                          | Индекс конечного листа (с нуля) для операции разделения. Например, `2` разделяет листы 0, 1 и 2.                                   |
| outFormat     | String | Параметр запроса                          | Формат выходных файлов после разделения. Поддерживаемые форматы включают `XLSX`, `PDF`, `CSV`, `JSON`, `HTML` и ещё более 30 других.|
| storageName   | String | Параметр запроса                          | _(Опционально)_ Имя облачного хранилища, где находится исходная рабочая книга. Если не указано, используется хранилище по умолчанию.|
| outPath       | String | Параметр запроса                          | _(Опционально)_ Путь к целевой папке облачного хранилища, куда будут сохраняться разделённые файлы. Если не указано, файлы сохраняются в исходной папке. |
| outStorageName| String | Параметр запроса                          | Имя облачного хранилища, куда будут сохраняться выходные разделённые файлы.                                                       |
| fontsLocation | String | Параметр запроса                          | _(Опционально)_ Указывает путь к пользовательской папке облачного хранилища, содержащей файлы шрифтов для корректного отображения текста в PDF/изображениях. |
| region        | String | Параметр запроса                          | _(Опционально)_ Устанавливает региональные настройки (локаль) для форматирования чисел, дат и валют в выходных файлах (например, `"en-US"`, `"zh-CN"`, `"de-DE"`). |
| password      | String | Параметр запроса                          | _(Опционально)_ Если исходная рабочая книга защищена паролем, укажите пароль для её открытия.                                      |

## **Ответ**

```json
[
  {
    "Name": "ResponseFile",
    "DataType": {
      "Identifier": "File",
      "Reference": "Stream",
      "Name": "file"
    }
  }
]
```

Файл можно загрузить напрямую или сохранить в путь, указанный в `outPath`.

**Детали успешного ответа**

| Код состояния | Content‑Type               | Описание                                     |
| ------------- | -------------------------- | -------------------------------------------- |
| 200 OK        | `application/octet-stream` | Двоичный поток объединённого файла рабочей книги. |

**Коды HTTP-статусов**

| Код | Значение                | Описание                                                       |
| --- | ----------------------- | -------------------------------------------------------------- |
| 200 | OK (OK)                 | Фильтр применён успешно; ответ содержит данные о выполнении.  |
| 400 | Bad Request (Неверный запрос) | Отсутствуют или недопустимы параметры (например, неподдерживаемый тип файла). |
| 401 | Unauthorized (Неавторизовано) | Недействительный или отсутствующий JWT-токен.                 |
| 413 | Payload Too Large (Слишком большой объём данных) | Загруженный файл превышает допустимый размер.                 |
| 500 | Internal Server Error (Внутренняя ошибка сервера) | Непредвиденная ошибка сервера.                                 |

## Где следует использовать API для разделения удалённой электронной таблицы?

- **Распределение данных по отделам**: Разделить единую рабочую книгу, содержащую данные нескольких отделов, на отдельные файлы по отделам.
- **Распределение региональных отчётов**: Разделить национальные отчёты о продажах на отдельные региональные отчёты по регионам.
- **Распределение скрытых данных клиентов**: Разделить рабочую книгу, содержащую конфиденциальную информацию, на выделенный файл для клиентов.
- **Периодическое разделение отчётов**: Автоматически разделять сводные отчёты на еженедельные или ежедневные отчёты ежемесячно.
- **Мультиформатное распределение**: Разделить один файл Excel на несколько версий в разных форматах, таких как PDF, CSV, JSON и др., одновременно.
- **Разделение по шаблону**: Разделить файлы данных на стандартизированные выходные файлы на основе предопределённых шаблонов.
- **Предварительная обработка источника данных**: Разделить файл Excel на стандартизированный CSV-файл перед загрузкой данных в базу данных.
- **Подготовка данных для API**: Разделить большие наборы данных на более мелкие части, подходящие для передачи через API.
- **Распределение данных для микросервисов**: Разделить центральный файл данных на отдельные файлы, необходимые каждому микросервису.

## Почему следует использовать API для разделения удалённой электронной таблицы?

- **Удобен для разработчиков**: Aspose.Cells Cloud предоставляет SDK на множестве языков, что позволяет быстро разрабатывать решения, и сопровождается подробной документацией. По сравнению с созданием собственных решений для отрисовки графиков, это значительно снижает объём работы.
- **Снижение затрат на персонал**: Уменьшает необходимость в должностях, ответственных за консолидацию документов.
- **Оплата по факту использования**: Нет первоначальных инвестиций; вы платите только за фактически выполненные вызовы API.
- **Отсутствие затрат на обслуживание**: Не нужно обслуживать серверы, обновлять программное обеспечение или решать проблемы совместимости.
- **Сохранение сложного форматирования Excel** в универсально доступном формате PDF.
